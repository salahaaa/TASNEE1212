# 📋 تقرير: كيف تعمل خطة الإنتاج في نظام DateERP
**من واقع التصميم والبرمجة المنفّذة — مطابق لنموذج TAMAT555 v1.59 المعتمد**
التاريخ: 2026-08-27

---

## 1) الفكرة الحاكمة (القاعدة الذهبية)

> **الخطة تجمع عمليات الإنتاج في مستند واحد عند الحاجة، لكنها لا تجمع ملكية أو أرصدة العملاء؛ كل سطر في الخطة يحتفظ بمرجعه الكامل: العميل ← الشحنة ← الدفعة ← الصنف التام ← العبوة ← الكمية ← التاريخ ← الوردية ← الخط.**

لا يوجد أي دمج لكميات عملاء مختلفين، ولا أي تداخل في ملكية الدفعات — النظام يرفض برمجياً تخطيط دفعة عميل باسم عميل آخر.

---

## 2) مسار المعاملة (Workflow) — أربع مراحل

```
1. إعداد الخطة (المدير التنفيذي) 📝
        │  إدخال البنود والفحص الآلي للطاقة والأرصدة
        ▼
2. اعتماد المدير العام ⏳
        │  إرسال ← اعتماد (تُقفل الخطة) أو إرجاع للتعديل بملاحظات
        ▼
3. أوامر تشغيل الإنتاج ⚡
        │  من الخطة المعتمدة تُنشأ أوامر التشغيل وتُنفَّذ
        ▼
4. الإقفال المالي والمخزني 🔒
           إقفال الخطة يحرر الحجوزات غير المستهلكة
```

شاشة الخطة تعرض هذا المسار كشريط خطوات ملوّن يتقدم تلقائياً مع الحالة:
**مسودة 📝 ← بانتظار الاعتماد ⏳ ← معتمدة ومقفلة 🟢🔒 (أو معادة للتعديل ↩️)**

---

## 3) محددات الخطة (رأس المستند)

| المحدد | الوظيفة |
|---|---|
| كود الخطة | تلقائي من نظام الترقيم (PLN-...) |
| من تاريخ / إلى تاريخ | فترة الجدولة + أزرار «مدد سريعة»: 7/10/14/16/20/30 يوماً |
| نوع الخطة | يومية (تاريخ واحد — يُقفل «إلى تاريخ») / أسبوعية / فترة |
| عنوان الخطة * | إلزامي قبل الحفظ |
| الوردية * | تعرض اسم الوردية وساعاتها الفعلية |
| خط الإنتاج | يعرض اسم الخط وطاقته لكل وردية |
| البيان والتوجيه | تعليمات التوزيع وأولويات التشغيل |

### نطاق التخطيط (اختيار جوهري):
- **👥 خطة لعدة عملاء (مجمع):** يظهر عمود «العميل المالك» في جدول البنود، ونافذة الاختيار تعرض دفعات كل العملاء.
- **👤 خطة لعميل محدد:** العميل يُحفظ في رأس النموذج فيُخفى عموده من الجدول؛ اختيار العميل يفتح نافذة دفعاته فوراً.

## 4) إدخال البنود — نافذة اختيار الأصناف والدفعات (مطابقة لـ v1.59)

الزران:
- **👤 أصناف العميل (F4):** دفعات العميل المحدد فقط.
- **👥 أصناف العملاء (F6):** النافذة المجمعة لكل العملاء.

النافذة المنبثقة = **محرر صفّي**: كل دفعة متاحة بالمستودع صف مستقل قابل للتحرير:

| عمود | السلوك |
|---|---|
| ☑ اختيار | تحديد متعدد + مربع «تحديد الكل» + فلتر بحث سريع |
| العميل والدفعة | اسم العميل + كود الدفعة + الشحنة + الخام |
| المتاح (كجم) | = رصيد المخزون − المحجوز لخطط نشطة |
| الصنف التام * | قائمة أصناف المجموعة 002 (المنتج النهائي) |
| العبوة والقوالب | الكرتون وعدد قوالبه ووزن القالب |
| الكراتين | إدخال يدوي |
| الخام المطلوب | **يُحسب تلقائياً = الكراتين × وزن العبوة (كجم)** |
| تنبيه الطاقة ⚡ | لحظي لكل صف: «✓ يتطلب 2.5 س (المتبقي 6.0 س)» أو «⚠️ يتجاوز الطاقة!» |

ثم **➕ إدراج** للصف الواحد أو **📥 إنزال الدفعات المحددة** للجماعي — البنود تنزل لجدول الخطة كاملة المراجع.

الخيارات الإضافية: **⚖ اقتراح توزيع عادل** (توزيع البنود بالتناوب على أيام الخطة) و**✍️ إضافة يدوي** (بند بلا دفعة).

## 5) محرك الطاقة الإنتاجية (حسب الوردية ومن شاشة الأصناف)

القاعدة المطبّقة:
- **الطاقة القصوى لكل صنف/وردية هي المُدخل** (من شاشة الأصناف).
- **المعدل بالساعة قيمة محسوبة** = الطاقة ÷ ساعات الإنتاج الفعلية للوردية — وليست مدخلاً مستقلاً قابلاً للتعارض.
- تغيير ساعات الوردية يعيد اشتقاق طاقة كل صنف تلقائياً من معدله المحفوظ.

المعادلات في الكود:
```
ساعات الوردية الفعلية   = الساعات الإجمالية − التوقفات المخططة
المعدل (كرتون/ساعة)     = الطاقة القصوى ÷ الساعات الفعلية
الساعات المطلوبة للبند  = الكراتين ÷ المعدل
الطاقة المتاحة للوردية  = الساعات الفعلية − الساعات المستهلكة من كل الخطط (نفس اليوم/الوردية/الخط)
```

شريط طاقة الوردية أعلى الشاشة يعرض لحظياً:
**«إجمالي المجدول: X كرتون (Y ساعة) من أصل Z كرتون (W ساعات) + الساعات المتبقية»** بالأخضر إن وُجدت طاقة شاغرة وبالأحمر إن استُنفدت.

## 6) فحوصات الحفظ الآلية (لا يُحفظ أي بند يخالفها)

عند الحفظ يفحص النظام **كل بند** ويرفض الحفظ برسالة تفصيلية إن تجاوز:

1. **رصيد الدفعة:** الكمية المطلوبة ≤ المتاح من الدفعة (بعد خصم حجوزات الخطط الأخرى وحجوزات نفس الخطة).
2. **الطاقة الإنتاجية:** الساعات المطلوبة للبند ≤ الساعات المتبقية للوردية في ذلك اليوم/الخط — والرفض يعرض: الطاقة المتاحة بالكراتين، المطلوب، الزيادة، وتفصيل الساعات.
3. **الملكية:** دفعة العميل لا تُخطط إلا باسم صاحبها — رسالة «الدفعة مملوكة لعميل آخر».

### حجز الدفعات (الآلية المحورية):
- بمجرد إنشاء الخطة يُحدَّث حقل **المحجوز** على كل دفعة: `المحجوز = مجموع كميات كل الخطط النشطة (غير المقفلة/الملغاة) على هذه الدفعة`.
- **المتاح للتخطيط = رصيد المخزون − المحجوز** — فلا يمكن لخطتين حجز نفس الكمية.
- تعديل/حذف/إلغاء اعتماد/إقفال الخطة يعيد احتساب الحجوزات تلقائياً (تحرير الكميات غير المستهلكة).

## 7) سير الاعتماد

| الإجراء | الشرط/الأثر |
|---|---|
| 📤 إرسال للاعتماد | خطة مسودة فيها بنود → حالة «بانتظار الاعتماد» |
| ✅ اعتماد المدير العام | تُقفل الخطة 🔒 وتصبح جاهزة لأوامر التشغيل (باسم المعتمد وتاريخه) |
| ↩ إرجاع للتعديل | بملاحظات تظهر للمخطط وتعاد الخطة لمسودة |
| إلغاء الاعتماد | مسموح فقط **إن لم تصدر منها أوامر إنتاج** — يعيد فتحها ويعيد احتساب الحجوزات |
| حذف الخطة | للمسودات فقط؛ ممنوع حذف معتمدة أو صدرت منها أوامر |
| الإقفال النهائي | يحرر الحجوزات غير المستهلكة |

## 8) ماذا بعد الاعتماد؟ (دورة التنفيذ الكاملة المرتبطة بالخطة)

كل بند خطة يشق طريقه محافظاً على مرجعه الكامل:

```
الخطة المعتمدة
   ▼ أمر تشغيل (مرتبط بالبند عبر PlanItemId)
   ▼ جلسة تنفيذ: تسجيل الكمية المنتجة
        • ممنوع إنتاج أكثر من المخطط للأمر (حارس تجاوز الإنتاج)
        • الكمية توزع على بنود الأمر بالترتيب
        • يُحدَّث تلقائياً: بند الخطة.المنتج
   ▼ فحص الجودة (مرة واحدة لكل جلسة — ممنوع التكرار)
        • مقبول / مرفوض + تسجيل النواتج الثانوية (حشف/نوى) بالكيلو
        • يُحدَّث تلقائياً: بند الخطة.المقبول
   ▼ استلام الإنتاج التام في مخزن التام (بمرجع العميل المالك)
   ▼ تسليم العميل
        • يُحدَّث تلقائياً: بند الخطة.المسلَّم (لا يتجاوز المتبقي)
        • الفوترة على المسلَّم فعلياً فقط — ممنوع تكرار الفوترة لنفس الكمية
```

لكل بند حالة تنفيذ مستقلة تُحسب آلياً: **لم يبدأ ⏳ / قيد التنفيذ 🏭 / جزئي 🟠 / مكتمل ✅**.

## 9) المتابعة والرقابة على الشاشة

- **خطة اليوم:** اختيار تاريخ → بنود اليوم لكل الخطط مع: الساعات المطلوبة، المستهلكة، المتبقية، المنتج، المسلَّم، الحالة. مع زر تعديل البند (تاريخ/كمية/وردية) **لبنود المستقبل فقط** — البند المنفَّذ أو الذي مضى تاريخه يتطلب صلاحية إدارية، وأي تعديل يعيد فحص الطاقة تلقائياً ويفحص رصيد الدفعة عند زيادة الكمية.
- **حالة أيام الخطة:** لكل يوم: عدد البنود، المخطط، المنتج، الحالة (اكتمال يوم لا يعني اكتمال الخطة).
- **تقدم كل عميل مستقل:** لكل عميل: مخطط/منتج/مقبول/مسلَّم/متبقي + حالته الخاصة — **اكتمال عميل لا يُكمل الخطة**.
- **سجل الخطط:** كل الخطط المحفوظة (نقر مزدوج للفتح) مع عدد عملائها وبنودها وكمياتها وحالتها.
- **التنقل:** أول/سابق/تالي/آخر بين الخطط + تراجع لمسح التعديلات.

## 10) قواعد الحماية المطبّقة برمجياً (خلاصة)

1. لا تجاوز لطاقة الوردية — بالكراتين والساعات معاً.
2. لا تجاوز لرصيد الدفعة — بالحجز المسبق لكل الخطط النشطة.
3. لا دمج لملكية العملاء — الدفعة لصاحبها في كل المراحل.
4. لا إنتاج أكثر من المخطط على مستوى الأمر.
5. لا تكرار فحص الجودة لنفس الجلسة.
6. لا فوترة مكررة — الفوترة على المسلَّم فقط وحتى سقفه.
7. لا حذف/إلغاء اعتماد لخطة صدرت منها أوامر.
8. لا تعديل لبنود منفَّذة أو تاريخها مضى إلا بصلاحية إدارية.
9. المعاملات ذرية بالكامل: نجاح كامل أو تراجع كامل (لا حفظ جزئي، حتى عند انقطاع الشبكة).
10. ترحيل تلقائي شامل لمخطط قاعدة البيانات عند الإقلاع — أي جدول أو عمود جديد يُضاف لقواعدكم القديمة بلا حذف بيانات.

## 11) الجداول التي تقوم عليها الخطة

| الجدول | الدور |
|---|---|
| ProductionPlans | رأس الخطة: الكود، العنوان، النوع، الفترة، الوردية، الخط، الحالة، الاعتماد، الإقفال |
| ProductionPlanItems | بنود الخطة بالمرجع الكامل + تقدم مستقل: المنتج/المقبول/المسلَّم/حالة التنفيذ |
| Lots | الدفعات: الرصيد، المحجوز، المتاح، المالك، الشحنة |
| Shipments / ShipmentItems | الشحنات المستلمة مرجعاً للدفعات |
| Products + ProductShiftCapacities | الأصناف التامة (002) وطاقتها لكل وردية |
| Shifts | الورديات وساعاتها الفعلية والتوقفات |
| ProductionOrders / Items | أوامر التشغيل المولدة من الخطة (مرتبطة بالبند) |
| ProductionExecutions | جلسات التنفيذ الفعلي |
| QualityChecks / ByProducts | فحوصات الجودة والنواتج الثانوية بالكيلو |
| FinishedGoodsReceipts / CustomerDeliveries | استلام التام وتسليم العملاء والفوترة |
