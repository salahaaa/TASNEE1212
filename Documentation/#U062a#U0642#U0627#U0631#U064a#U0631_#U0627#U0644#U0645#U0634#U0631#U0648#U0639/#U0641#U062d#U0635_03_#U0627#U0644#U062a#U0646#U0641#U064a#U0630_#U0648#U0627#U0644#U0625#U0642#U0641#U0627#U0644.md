# فحص معمّق — التنفيذ وإقفال يوم الإنتاج (MRPMPS1010)

**الملفات:** `ExecutionView.xaml` (154) · `ExecutionView.xaml.cs` (436) · `ExecutionService.cs` (685)

## 1) 🔴🔴 الإقفال يُدمّر أساس «الخطة مقابل الفعلي» — **مُثبت بالتشغيل**

**السبب — سطران:**
```csharp
// ExecutionService.ClosePlanItems
pi.ProducedQtyKg += produced;
pi.PlannedQtyKg   = pi.ProducedQtyKg;    // ← يستبدل المخطط بالمنتَج
pi.ExecutionStatus = "Completed";
// وقبلهما على بند الأمر:
oi.ProducedQtyKg += produced;
oi.PlannedQtyKg   = oi.ProducedQtyKg;
```

**الاختبار:** خطة 10,000 كجم / 1,000 كرتون ← إقفال **6,000 كجم فقط** (إنجاز 60%):
```
=== BEFORE closing ===
  plan item: PlannedQtyKg=10000  PlannedCartons=1000  ProducedQtyKg=0

=== AFTER closing ===
  PlannedQtyKg   = 6000     <-- was 10000
  ProducedQtyKg  = 6000
  PlannedCartons = 1000     <-- NOT updated
  => achievement as PlanVsActual computes it = 100.0%   (real achievement was 60.0%)

=== report 'plan_vs_actual' actual output ===
  المخطط (كجم)=6000 | المخطط (كرتون)=1000 | المنتج=6000 | إنجاز=100 | مكتملة ✅
  summary: إنجاز إجمالي ٪ = 100.0
```

**ثلاث علل في سطر واحد:**
1. **الإنجاز يظهر 100% والفعلي 60%** ← **نقص الإنتاج غير مرئي إطلاقاً** في التقارير.
2. **عمودا المخطط يتناقضان**: 6,000 كجم مقابل 1,000 كرتون (أي 10,000 كجم) — لأن `PlannedCartons` لا يُعدَّل.
3. **أساس الخطة يُدمَّر** — لا يمكن معرفة ما كان مخططاً أصلاً.

**وتبعاً لذلك:** رسالة الإقفال قالت *«🔒 أُقفلت الخطة تلقائياً **لاكتمال إنتاج بنودها**»* بينما الإنتاج **لم يكتمل** (6,000 من 10,000). فالإقفال التلقائي يُطلَق بسبب إعادة الكتابة نفسها.

**السبب المعلن صحيح والوسيلة خاطئة:** التعليق يقول «يُخفض المخطط للمنتَج فيُحرر باقي الحجز آلياً» — تحرير الحجز مطلوب، لكن المطلوب حقل مستقل (`ReleasedQtyKg`) أو حفظ `OriginalPlannedQtyKg`، لا محو المخطط.


## 5) 🟠 `FirstOrDefault` لبند الأمر — أمر واحد فقط، وبلا ترتيب
`ClosePlanItems:282`: `var oi = Db.ProductionOrderItems.FirstOrDefault(i => i.PlanItemId == pi.Id);` — إن كان للبند أوامران (توزيع على ورديتين) يُربط **الأول عشوائياً**، وقد يكون الملغي.

## 6) 🟠 لا تاريخ إقفال يختاره المستخدم، ولا فلترة باليوم
`ClosingDate = DateTime.Now` ثابت · `Plan_Changed` يحمّل **كل بنود الخطة** بلا فلتر تاريخ ولا عمود تاريخ ← **نفس علّة شاشة الأوامر**: خطة 14 يوماً تُقفل كمستند واحد بلا تمييز أيام.

## 8) ✅ ما هو صحيح (إنصاف)
- الحراس: خطة معتمدة · غير مقفلة · كميات غير سالبة · `OVER_PLAN` · `OUTPUTS_EXCEED` · `ALREADY_DONE`
- **المرتجع يعود بنفس العميل والدفعة** مع حركة مخزون مرتبطة بالمستند (تحققتُ: «أُعيد للمخزن الخام 4,000.0 كجم بنفس العملاء والدفعات»)
- `Require("execution", "Edit")` في الـ Backend
- المخرجات الثانوية **ديناميكية** من جدول `ByProducts` في جانب الإدخال (أعمدة تُولَّد وقت التشغيل)
- التوقفات بمدخل حر (ساعات + سبب) — بلا ثوابت
