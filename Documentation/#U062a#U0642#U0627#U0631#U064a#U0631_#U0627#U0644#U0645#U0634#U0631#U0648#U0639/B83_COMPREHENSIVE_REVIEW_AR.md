## 3) نقاط القوة (تُحسب للمشروع)

1. **معمارية طبقية حقيقية:** Core (نطاق) / Application (خدمات) / Infrastructure (EF) / Desktop (WPF) — والاعتماديات باتجاه صحيح (Application → Core + Infrastructure).
2. **`ServiceBase` ناضج:** معاملة ذرية لكل عملية + ترجمة تعارض التزامن لرسالة عربية + معالجة انقطاع الشبكة + تنظيف `ChangeTracker` بعد الفشل (يمنع تسرّب الكيانات).
3. **التزامن التفاؤلي:** `rowversion` على SQL Server وبديل GUID على SQLite + استثناء عربي موحد.
4. **التدقيق داخل المعاملة:** `AuditSaveChangesInterceptor` يختم الطوابع ويكتب `AuditLog` (قبل/بعد، مستخدم، جهاز) في نفس المعاملة — لا حركة بلا تدقيق.
5. **الأمان الأساسي سليم:** PBKDF2-SHA256 بـ 100,000 دورة + مقارنة زمنية ثابتة + DPAPI لكلمات SQL + قفل حساب بعد 5 محاولات مع فك تلقائي + انتهاء كلمة المرور + مهلة خمول للجلسة.
6. **قواعد أعمال مركزية:** `UnitsPolicy` (001/002/003/004)، `QualityGate`، `CapacityPolicy` — مصدر واحد للحقيقة بدل تشتتها في الشاشات.
7. **نظام صلاحيات هرمي + تفويض زمني:** أدوار/موارد/عمليات + استثناءات مستخدم + تفويض — مع 98 فحص `Require` في الخدمات.
8. **نضج الدعم الميداني:** `BootTrace` (أثر إقلاع خطوة بخطوة)، `SelfDiagnostic` (تشخيص ذاتي)، `BuildInfo.Stamp` (ختم البناء في العنوان) — حلول عملية لمشاكل حقيقية واجهها الفريق.
9. **CI يتجاوز المعتاد:** فحص "لا أزرار ميتة"، فحص RTL، ومنع `double` جديد — فحوصات بنيوية مخصصة لمنع عودة أعطال سابقة. ممارسة ممتازة.
10. **فلسفة `AcceptanceRunner`:** اختبار المسار الذي تسلكه الشاشات فعلياً والتحقق من الأثر في القاعدة — وُلد من درس حقيقي (اختبارات خضراء ومسار ميت). **لكن — انظر M6 — لا يُشغَّل في CI!**
11. **التعليقات التوثيقية العربية (§):** توثيق "السبب" لا "الماذا" (B-numbers + القرارات) — ممارسة صيانة ممتازة ونادرة.
12. **318 اختباراً** بتغطية سيناريوهات أعمال حقيقية (دورة كاملة، حراس، طاقات، تتبع، تقارير).

## 4) ملاحظات حرجة 🔴 (يجب المعالجة قبل التوسع)

### C1 — ترقيم المستندات غير آمن تحت التزامن (أخطر ملاحظة)
- **الموقع:** `src/DatesErp.Infrastructure/DependencyInjection.cs` — فئة `NumberingService.Next()`.
- **المشكلة:** النمط قراءة-تعديل-كتابة (`FirstOrDefault` ثم `LastSequence += 1`) **بلا قفل وبلا عزل معاملات**. جهازان يطلبان رقماً في نفس اللحظة سيقرآن نفس `LastSequence` ويولّدان **نفس الرقم**. حلقة `IsUsed` لا تحمي شيئاً لأنها تفحص البيانات **المحفوظة فقط**، والمعاملتين المتزامنتين لم تُحفظا بعد.
- **التعليق في الكود يدّعي "مضاد للتكرار نهائياً" — هذا الادعاء خاطئ تحت التزامن.** ما ينقذ البيانات اليوم هو الفهارس الفريدة (سيحدث استثناء `UNIQUE constraint` بدل تلف صامت) — أي أن نمط الفشل هو **خطأ يظهر للمستخدم** وقت الذروة.
- **الإصلاح المقترح (واحد منها):** تسلسل `SEQUENCE` في SQL Server + `HiLo`؛ أو معاملة بعزل `Serializable` مع `UPDLOCK, HOLDLOCK` على صف المخطط؛ أو على الأقل إعادة المحاولة التلقائية عند تعارض الرقم الفريد.

### C2 — لا توجد ترحيلات EF Migrations — مخطط مخصص هش
- **الموقع:** `Persistence/SchemaMigrator.cs` + الاعتماد على `EnsureCreated()`. لا يوجد أي مجلد Migrations في المشروع.
- **المشكلة:**
  - `BuildCreateTable` ينشئ **الأعمدة والمفتاح فقط** — بلا فهارس، بلا مفاتيح أجنبية، بلا قيود — للقواعد القديمة. أي أن القواعد المُرحَّلة تختلف بنيوياً عن القواعد الجديدة (فهارس ناقصة = بطء + غياب حماية التكرار التي يعتمد عليها C1!).
  - لا تراجع (downgrade)، ولا سجل ترحيلات موحّد، ولا فصل بين تغيير المخطط وتغيير البيانات.
  - `SweepNulls` يملأ القيم الفارغة بقيم اعتباطية (`'2000-01-01'`، `''`، `0`) **بصمت** — قد يغيّر دلالة بيانات قائمة دون أن يعرف أحد.
- **الإصلاح:** اعتماد EF Migrations رسمياً (المسار الطبيعي)، والإبقاء على `SchemaMigrator` كجسر ترقية لمرة واحدة للقواعد الميدانية القائمة فقط.

### C3 — ملف الحل `.sln` ناقص: لا يتضمن 3 من 5 مشاريع
- **الموقع:** `DateERP.sln` يتضمن فقط `DatesErp.Desktop` و`DatesErp.Tests` — مشاريع `Core` و`Application` و`Infrastructure` **غائبة** (تُبنى تبعياً عبر `ProjectReference` فقط). وكذلك `tools/AcceptanceRunner` و`audit/UnitRuleAudit` خارج الحل.
- **الأثر:** تجربة مطور جديد مربكة (Solution Explorer ناقص)، وخطر نسيان بناء/اختبار أدوات مهمة. إصلاحه دقائق (`dotnet sln add`).

### C4 — غياب كامل للبرمجة غير المتزامنة (صفر `async/await` في كل `src`)
- **المشكلة:** كل عمليات قاعدة البيانات والشبكة **متزامنة على خيط الواجهة**. أي تباطؤ شبكة = **تجميد كامل للتطبيق** حتى `Connect Timeout=8` ثوانٍ لكل عملية. في نظام شبكي متعدد الأجهزة هذا عيب تجربة استخدام بنيوي.
- **الإصلاح:** تحويل الخدمات إلى `async` تدريجياً (EF يدعمها أصلياً) مع مؤشر انشغال؛ كحد أدنى تغليف العمليات الطويلة مع منع النقر المزدوج.

### C5 — `decimal` يُخزَّن كنص! (`DatesErpDbContext.ConfigureConventions`)
- **المشكلة:** المحوّل `DecimalToStringConverter` بصيغة `"0.####"` يعني: (أ) **فقدان دقة** بعد 4 خانات؛ (ب) **المقارنة والترتيب في قاعدة البيانات نصية** (`'10' < '9'`) — أي `WHERE`/`ORDER BY`/`SUM` على هذه الأعمدة **خاطئة أو مستحيلة** على مستوى SQL؛ (ج) الفهارس عليها عديمة الجدوى.
- **الإصلاح:** `decimal(18,4)` حقيقي على SQL Server، والمحوّل النصي — إن لزم — يُقيَّد بمزوّد SQLite فقط. أو تخزين الوحدات الصغرى كأعداد صحيحة.

### C6 — انتهاك الطبقات: الواجهة تكتب في قاعدة البيانات مباشرة
- **المواقع (~30 ملفاً تستخدم `DbContext` في Desktop):** أخطرها:
  - `QualityView.xaml.cs:730` — `db.SaveChanges()` يكتب نتائج فحص ومعايير **متجاوزاً** `InspectionService` (قواعد الإلزام، أوزان الكراتين، فحص الصلاحيات).
  - `GroupsAndCategoriesWindow.cs:206` — إنشاء مخارج ثانوية بأكواد عشوائية `BP-<GUID>` متجاوزاً الترقيم المركزي وقواعد منع التكرار.
  - `QualitySetupWindow.cs` (4 مواضع)، `PermissionsView.xaml.cs:368`، `SystemInfoView.xaml.cs:141`.
- **الأثر:** قواعد الأعمال قابلة للتجاوز، منطق غير قابل للاختبار (خارج الـ 318 اختباراً)، وفحوصات `Require` الـ 98 لا تنطبق على هذه المسارات. ومع أن `ViewModelBase` موجود، **لا يستخدمه أي ملف** — فالـ MVVM معلن شكلياً والواقع Code-Behind (ملفات 1000+ سطر: `PlanningView` 1278، `QualityView` 1068).
- **الإصلاح:** نقل كل كتابة إلى خدمات `Application` + إضافة **اختبار معماري** يمنع `SaveChanges/Add/Remove` في مشروع Desktop (باستثناء `Bootstrapper`)، وتقسيم الشاشات العملاقة تدريجياً.

### C7 — أسماء الملفات العربية مكسورة الترميز (44 ملفاً/مجلداً)
- **المشكلة:** كل أسماء التوثيق والتنصيب العربية ظهرت بصيغة `#U062a#U0642...` — أي أن الـ ZIP نفسه **معطوب الترميز**. سكربتات التنصيب (`1-#U0628...bat`) و29 تقريراً ومجلد التقارير كلها بأسماء غير صالحة للاستخدام المباشر على أجهزة المستخدمين.
- **الإصلاح:** إعادة التغليف بأسماء UTF-8 سليمة (أو إنجليزية)، وفكّ المصدر في المستودع (H10) يقضي على المشكلة من جذورها.

## 7) منظور تطوير المشاريع والمنتج 📊

### 7.1 ما يسير بشكل صحيح (عملية)
- CI يعمل + فحوصات بنيوية مخصصة لمنع النكوص — نضج عملية فوق المعتاد لمشاريع بهذا الحجم.
- سجل قرارات عربي في الكود (§ + أرقام B) — يخفّض "عامل الحافلة" جزئياً.
- قائمة تحقق ميدانية (§38/§40: اختبار 3 أجهزة + اختبار الانقطاع) — **لكنها غير منفذة بعد** (تتطلب موقع العميل).

### 7.2 المخاطر الإدارية
1. **تركيز المعرفة:** أسلوب التعليقات الموحد يوحي بمؤلف واحد رئيسي — "عامل الحافلة = 1". يلزم مراجعة أقران + توثيق قرارات معمارية (ADR) خارج الكود.
2. **زحف النطاق:** الرقم B83 (83 بناء) + 29 تقريراً داخلياً يوحي بدورات طويلة بلا إصدارات مجمدة للعميل — يُنصح بتجميد نطاق كل إصدار (Release scope freeze).
3. **فجوة التحقق الميداني:** أهم اختبارين (تعدد أجهزة حقيقي، انقطاع شبكة) مؤجلان للموقع — وC1/H2/H4 تجعل نتيجتهما غير مضمونة. يجب تنفيذهما **بعد** إصلاح التزامن لا قبله.
4. **النشر اليدوي:** `.bat` + نسخ مجلدات + `DateERP_Publish` — يعمل لكنه عرضة لخطأ "التحديث لا يصل" (الذي عالجه الفريق بـ `BuildInfo` بدل معالجة السبب: تحديث تلقائي). على المدى المتوسط: MSIX أو ClickOnce أو Squirrel للتحديث الذاتي.
