# تصميم حلّ المواد المساعدة والصرف مقابل الإنتاج الفعلي
**التاريخ:** 2026-08-30 | **الحالة:** مقترح للمراجعة — لا تعديل قبل الاعتماد | **النطاق:** المواد المساعدة، الكراتين بالماركات، الصرف، التكلفة

---

## 1) نتائج الفحص — جذور المشاكل الثلاثة (بأدلة من الكود)

| # | المشكلة الظاهرة | الجذر الفعلي في النظام الحالي |
|---|---|---|
| 1أ | لا يمكن إضافة مجموعة مواد مساعدة | لا يوجد كيان «مجموعات» أصلاً: `AuxiliaryMaterial.MaterialCategory` نص حر، ولا توجد أي دالة حفظ للمواد في `MasterDataService` ولا نموذج إدخال في `MaterialsView` (الشاشة قراءة فقط) — المواد الحالية مخلوقة بالبذر فقط |
| 1ب | خلط كراتين العملاء بالمخزون | كرتونة كل العملاء = مادة واحدة `AUX-CARTON`؛ لا بُعد عميل/ماركة/جودة في `ConsumptionFormula` (منتج×عبوة فقط) ولا في رصيد المادة؛ ولا تكلفة مرتبطة بالعميل |
| 2 | الصرف على المخطط لا الفعلي | `ProductionOrderService.ApproveOrder` (أسطر ~428‑440): عند الاعتماد تُرحَّل حركة صادر **كاملة** بقيمة `CalculatedQty` المحسوبة من **كراتين الخطة**، ويُضبط `ActualIssuedQty = CalculatedQty`؛ لا توجد أي تسوية عند الإقفال/التنفيذ ⇒ خطة 8,000 وإنتاج 6,000 تعني 2,000 كرتون موادها مصروفة بلا استحقاق |
| 3 | لا تحكم بالمطلوب/الاختياري/المعامل | `ConsumptionFormula` حقولها: ProductId/PackagingTypeId/MaterialId/QtyPerUnit/IsActive فقط — لا `RequiredMode` ولا تجاوز لكل عميل، ولا محرر شاشة |
| تكلفة | `DefaultCost` موجود لكنه لا يُستخدم في تقييم الصرف/الاستهلاك ولا في تقارير تكلفة الأمر/العميل |

**خلاصة التشخيص:** الخلل ليس في شاشة الصرف وحدها بل في **نموذج الدورة**: الصرف حدثٌ واحد نهائي عند الاعتماد بدل دورتين (حجز عند الاعتماد ↔ استهلاك عند الإقفال)، وغياب بُعدي «العميل/الماركة» و«المجموعات القابلة للإدارة».

## 2) التصميم المقترح

### 2.1 مجموعات ومواد قابلة للإدارة (حل 1أ و3)
- جدول جديد `AuxGroups { Code, NameAr, IsActive }` + إدارة كاملة من شاشة المواد (إضافة/إعادة تسمية/تعطيل) — لا ثوابت بالكود.
- توسعة `AuxiliaryMaterial`: `GroupCode`، `QualityGrade` (عادي/مقوى/ماركة...)، `LastCost` (متوسط متحرك)، مع **CRUD كامل** من الشاشة.
- بذور أولية: مجموعة «كراتين العملاء»، «مواد التغليف»، «مواد التشغيل» — ثم يضيف المستخدم ما شاء.

### 2.2 مواصفات العميل — منع خلط الكراتين والتكاليف (حل 1ب)
- جدول جديد `AuxCustomerSpec { CustomerId, ProductId?, PackagingTypeId?, MaterialId, BrandName, UnitCost, Priority }`:
  «كرتون عميل X لصنف Y = المادة K بماركة Z وتكلفة U».
- محرك الاختيار عند الحساب: **مطابقة عميل+صنف ← عميل+عبوة ← عميل ← افتراضي المنتج** (أعلى أولوية يفوز).
- **حارس الصرف**: إذا وُجدت مواصفة ملزمة للعميل على مادة كرتون، يُرفض صرف أي مادة أخرى لأمر هذا العميل ⇒ استحيل خلط كراتين العملاء منطقياً؛ وفيزيائياً كل ماركة مادة مستقلة برصيدها وتكلفتها.
- التكلفة: كرتون العميل يُقيَّم بـ `UnitCost` المواصفة؛ بقية المواد بمتوسط متحرك `LastCost`.

### 2.3 الصرف مقابل الفعلي — دورتان بدل حدث واحد (حل 2)
**المرحلة 1 — الاعتماد (حجز/صرف مخطط):** تبقى الحسابات من المعادلات لكنها تُقيَّد حركة `MaterialReservation` (محجوز غير مستهلك)؛ `ActualIssuedQty` = المسحوب فعلياً من المخزن إن قرر أمين المخزن الصرف الفيزيائي، وإلا يبقى حجزاً.
**المرحلة 2 — الإقفال اليومي (الاستهلاك الفعلي):** لكل أمر متأثر: `استهلاك = كراتين المنفذ الفعلية × معامل المعادلة` ⇒ ترحيل `MaterialConsumption`؛ والفرق `المصروف/المحجوز − المستهلك` يُقيَّد آلياً **مرتجع مساعد** `MaterialReturn` إلى WAUX (أو يُرحَّل لليوم التالي حسب سياسة الأمر: حقل `AuxPolicy = Return | Carry`).
**مصير الـ2,000 المتبقية:** حجزها قائم على بنود الخطة غير المقفلة؛ عند إنتاجها لاحقاً تُستهلك حينها؛ وعند إقفال الخطة نهائياً يُعاد أي حجز غير مستهلك آلياً ⇒ **لا صرف بلا إنتاج فعلي أبداً**.
**الفاصل وبقية المواد:** تمر بنفس محرك المعادلات (معامل لكل كرتون) فتُستهلك فعلياً بنفس القاعدة؛ المخرجات الثانوية خارج المعادلات (مخرجات وليست مدخلات).
**حراس:** مستهلك ≤ مصروف؛ مصروف ≤ متبقي الخطة × معامل؛ المرتجع يزيد الرصيد؛ كل حركة بمرجع مستندها.

### 2.4 محرر المعادلات المرن (حل 3)
توسعة `ConsumptionFormula`: `RequiredMode ∈ {Required, Optional, Unused}` + `CustomerId?` + الإبقاء على `PackagingTypeId?`.
محرر داخل شاشة المواد/الأصناف: لكل منتج تام صفوف (المادة، المعامل لكل كرتون، الوضع، تجاوز عبوة/عميل)، مع أزرار إضافة/تعطيل، وتسجيل تغييرات في التدقيق.

### 2.5 التكلفة والتقارير
- تحديث `LastCost` عند أي وارد مساعد (سند شراء/إضافة رصيد مستقبلاً).
- تقرير «تكلفة المواد لكل أمر/عميل»: Σ المستهلك × التكلفة (مواصفة العميل أولاً) + مقارنة بالمخطط + انحراف التكلفة.
- تقرير «المواد المساعدة: محجوز/مصروف/مستهلك/مرتجع/رصيد» لكل مادة/مجموعة/فترة.

## 3) ما سيتأثر (جداول/حقول/منطق/شاشات)

| الطبقة | التغيير |
|---|---|
| جداول جديدة | `AuxGroups`، `AuxCustomerSpec` |
| توسعات | `AuxiliaryMaterial(+Group,Quality,LastCost)`، `ConsumptionFormula(+RequiredMode,+CustomerId)`، `ProductionOrder(+AuxPolicy)`، تفعيل حالات `ProductionOrderMaterial` (محجوز/مصروف/مستهلك/مرتجع)، `PlanClosing(+لقطة تسوية المواد)` |
| حركات مخزون | أنواع مرجعية جديدة: `MaterialReservation`، `MaterialConsumption`، `MaterialReturn` |
| المنطق | `ApproveOrder` (حجز بدل صرف نهائي)، `ClosePlanItems` (استهلاك فعلي + مرتجع آلي)، محرك اختيار المواصفات، حراس الصرف |
| الشاشات | المواد: مجموعات+CRUD+محرر معادلات+مواصفات عملاء؛ مستند الأمر: عرض الحالات الأربع؛ الإقفال: قسم تسوية المواد؛ التقارير: تقريران جديدان |
| الصلاحيات | عمليات جديدة على مورد `materials` (إدارة مجموعات/معادلات/مواصفات) |

## 4) ضمانات مطلوبة وكيف تتحقق
1. **لا خلط كراتين عملاء**: مادة مستقلة لكل ماركة + مواصفة ملزمة + حارس صرف يطابق عميل الأمر بالمواصفة.
2. **لا صرف فوق الفعلي**: نموذج الحجز/الاستهلاك/المرتجع + الحراس الثلاثة + إرجاع آلي عند إقفال الخطة.
3. **مرونة كاملة**: مجموعات ومواد ومعادلات ومواصفات تُدار من الشاشات، وتسجل بالتدقيق.

## 5) خطة تنفيذ مقترحة (4 مراحل، كل مرحلة تُسلَّم مختبرة)
م1: المجموعات + CRUD المواد + الترحيل الآلي للجداول. م2: محرك الحجز/الاستهلاك/المرتجع وربط الإقفال + الحراس. م3: مواصفات العملاء + التكلفة + محرر المعادلات. م4: التقارير + الصلاحيات + اختبارات قبول (سيناريو 8,000/6,000 يختبر المرتجع الآلي والـ2,000 المتبقية).

## 6) قرارات مطلوبة منكم (مع توصيتنا)
1. سياسة فرق الصرف: **مرتجع آلي** أم ترحيل لليوم التالي؟ (نوصي: مرتجع آلي افتراضياً مع خيار Carry لكل أمر).
2. التقييم: **متوسط متحرك** (نوصي) أم آخر سعر؟
3. كراتين العملاء: مادة مستقلة لكل ماركة (نوصي) أم مادة واحدة بسمات دفعة؟
4. هل يُفعَّل الصرف الفيزيائي عند الاعتماد وجوبياً أم يبقى حجزاً حتى الإقفال؟ (نوصي: حجز، والصرف الفيزيائي اختيار أمين المخزن).

**بانتظار مراجعتكم واعتمادكم (أو تعديل القرارات الأربعة) لأبدأ التنفيذ مرحلةً مرحلة.**
