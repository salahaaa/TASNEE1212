# Date ERP — نظام إدارة وتصنيع التمور

[![DateERP CI](https://github.com/salahaaa/TASNEE1212/actions/workflows/ci.yml/badge.svg)](https://github.com/salahaaa/TASNEE1212/actions/workflows/ci.yml)

تطبيق **سطح مكتب شبكي متعدد المستخدمين** لإدارة وتصنيع التمور — من استلام الخام حتى تسليم العميل.

| | |
|---|---|
| **الإصدار** | `1.45.1` — ختم البناء `2026-09-05 B96` |
| **المنصة** | .NET 8 · WPF (`net8.0-windows`) · Windows 10/11 x64 |
| **قاعدة البيانات** | SQL Server 2016+ عبر EF Core (وضع محلي SQLite للجهاز المفرد) |
| **الواجهة** | عربية بالكامل · RTL · ثيم أخضر/ذهبي |
| **النشر** | Self-contained — لا يحتاج الجهاز الهدف تثبيت .NET |

---

## بنية الحل

```
src/
  DatesErp.Core/            النطاق: الكيانات، القيم، الواجهات، الاستثناءات
  DatesErp.Application/     منطق الأعمال: 25+ خدمة (تخطيط، إنتاج، جودة، تسليم…)
  DatesErp.Infrastructure/  EF Core، الهجرة، التدقيق، الجلسة، تجزئة كلمات المرور
  DatesErp.Desktop/         واجهة WPF — 25+ شاشة (نقطة الدخول: DateERP.exe)
tests/DatesErp.Tests/       ~70 ملف اختبار (xUnit)
tools/AcceptanceRunner/     مُشغّل اختبارات القبول
audit/UnitRuleAudit/        أداة تدقيق قاعدة الوحدات
Installer/                  حزمة تنصيب عربية (bat / ps1 / sql)
Documentation/              الأدلة، قوالب الطباعة، وتقارير المشروع
```

---

## البناء والتشغيل

```bash
dotnet restore DateERP.sln
dotnet build   DateERP.sln -c Release
dotnet test    tests/DatesErp.Tests/DatesErp.Tests.csproj -c Release
```

**بناء حزمة التنصيب:** شغّل `Installer/1-بناء_الحزمة.bat` على جهاز المطوّر، ثم `Installer/2-تنصيب.bat` على كل جهاز هدف.
التفاصيل الكاملة في [`Installer/README_التنصيب.md`](Installer/README_التنصيب.md).

## دورة العمل التي يغطيها النظام

```
الاستلام ← الدفعات ← خطة الإنتاج ← أوامر الإنتاج ← صرف المواد
   ← التنفيذ والجلسات ← الجودة والفحص ← الإنتاج التام ← تسليم العميل
```

مع: التتبع الكامل للصنف، إدارة الكراتين والمواد المساعدة، أرصدة وحركات المخزون،
15+ تقريراً (طباعة أصلية + PDF + Excel)، مستخدمون وصلاحيات (7 أدوار × 16 وحدة)،
سجل تدقيق، تزامن تفاؤلي (`rowversion`)، ونسخ احتياطي.

## ضوابط الجودة (CI)

يفرض [`.github/workflows/ci.yml`](.github/workflows/ci.yml) على كل PR:

- بناء Release بلا أخطاء + نجاح كل الاختبارات
- سقف تحذيرات (يُخفَّض تدريجياً)
- **فحوصات بنيوية:** منع الأزرار الموصولة بمعالج فارغ · التحقق من `FlowDirection=RightToLeft` · منع إضافة حقول `double` جديدة في الكيانات (استخدم `decimal`)
